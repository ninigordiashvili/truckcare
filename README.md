# Truck Care

სატვირთოების გასვლითი სერვისის აპი: მძღოლი → ოპერატორი/უფროსი → ხელოსანი ადგილზე → ნაწილი → ინვოისი.
Expo (iOS + Android), ერთი კოდი, სამი როლი.

## გაშვება

```bash
npm install
npx expo start --ios     # ან --android
```

ქვემოთ, ეკრანის ბოლოს, სამი ღილაკია — **მძღოლი / ხელოსანი / უფროსი**. ეს დემო-გადამრთველია:
რეალურ აპში როლი ავტორიზაციიდან მოდის, არა ღილაკიდან.

## რა მუშაობს

| ნაკადი | სად |
|---|---|
| მანქანის არჩევა 75-იდან (ნომრით, მოდელით ან VIN-ით) | მძღოლი → ჩემი მანქანა |
| „გაფუჭდა მანქანა“ → AI კითხულობს ერთ კითხვას → რჩევა, თვითონ გამოასწოროს | მძღოლი → ჩატი |
| ნაწილის ძებნა ჟარგონით („შკორნი“) → შეთავაზებები → შეკვეთა | მძღოლი → ნაწილი |
| გამოძახება: აღწერა, ფოტო, ლოკაცია → თიქეთი | მძღოლი → სასწრაფო |
| სტატუსი ნაბიჯ-ნაბიჯ | მძღოლი → ჩემი საქმე |
| ეტაპების მონიშვნა, საათები, ჩანაწერი | ხელოსანი → თიქეთი |
| ნაწილის შეკვეთა: თვითონ წაიღებს თუ კურიერი მოიტანს | ხელოსანი → ნაწილი მჭირდება |
| დაფა, ფილტრები, ხელოსნის მიბმა | უფროსი → დაფა |
| ინვოისი თიქეთიდან თვითონ იკრიბება (ნაწილი + მიტანა + გასვლა + საათები + დღგ) | უფროსი → თიქეთი |

ყველა მოქმედება ერთ მდგომარეობაშია: მძღოლის გამოძახება მაშინვე ჩანს უფროსის დაფაზე,
ხელოსნის შეკვეთა — ინვოისში.

## მონაცემები

- `src/data/fleet.js` — **რეალური ავტოპარკი**: 75 სატვირთო (ATEGO, ACTROS, AXOR, ANTOS, HINO, CANTER)
  და 10 ავტოსერვისი. გადმოტანილია `VIN CODES.xlsx`-იდან.
- `src/data/knowledge.js` — ტექნიკური ბაზის ნიმუში:
  - `PARTS` — ნაწილი → **ჟარგონი** → OEM → მომწოდებლების შეთავაზებები.
    `verified: false` ნიშნავს, რომ ფასი ძველი პასუხიდანაა და აპი ამას პირდაპირ წერს.
  - `SYMPTOMS` — სიმპტომი → ერთი დამაზუსტებელი კითხვა → ნაბიჯები → სავარაუდო ნაწილი.
    `confirmed: false` → აპი ამბობს „ეს ვარაუდია, წიგნით დადასტურებული არაა“.
  - `TECHS`, `CLIENTS` — ოთხი ხელოსანი და კლიენტი კომპანიები.

ფასები, კლიენტების სახელები და ტელეფონები დემოა. სატვირთოები და სერვისები — ნამდვილი.

## რა არ არის და შემდეგ რა მოდის

- **სერვერი არ არის.** მდგომარეობა მეხსიერებაშია (`src/store.js`), აპის დახურვისას იკარგება.
  შემდეგი ნაბიჯი: API + Postgres, იგივე ობიექტებით (tickets, parts, orders, invoices).
- **AI ლოკალურია** — საკვანძო სიტყვებით ეძებს `SYMPTOMS`-ში. რეალური ვერსია იგივე ფორმით
  იმუშავებს, ოღონდ მანუალებზე ძიებით; მთავარი წესი უცვლელია: პასუხი მხოლოდ ბაზიდან,
  დაუდასტურებელი — ასე მონიშნული.
- **ნაწილების კატალოგი** ექვსი ჩანაწერია. ნამდვილი კატალოგი TecDoc-ის ლიცენზიას მოითხოვს.
- **ჟარგონის ლექსიკონი** ოთხ ხელოსანთან ერთად უნდა შეივსოს — ეს ის მონაცემია, რომელიც
  ვერსად იყიდება.
- კურიერით მიტანა ინტერფეისშია; გამოძახების ინტეგრაცია ცალკე საკითხია.

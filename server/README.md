# Truck Care — სერვერი

Express 5 + Prisma. დეველოპმენტში SQLite, პროდაქშენში Postgres
(`schema.prisma`-ში `provider` შეიცვლება და `prisma migrate` გაეშვება — სხვა არაფერი).

## გაშვება

```bash
npm install
npm run db:push     # ბაზის შექმნა სქემიდან
npm run db:seed     # ავტოპარკი, ნაწილები, სიმპტომები, ხალხი
npm run dev         # http://localhost:4000
npm run smoke       # სრული ციკლის შემოწმება: გამოძახებიდან ინვოისამდე
```

`npm run db:studio` — ბაზის დათვალიერება ბრაუზერში.

## ავტორიზაცია

`POST /auth/login { phone }` → `{ token, user }`. ტოკენი ყველა მოთხოვნას ახლავს:
`Authorization: Bearer <token>`.

**დეველოპმენტში SMS-კოდი არ არის** — მხოლოდ ნომერი. პროდაქშენამდე აქ ერთი ნაბიჯი ემატება
(კოდის გაგზავნა და შემოწმება); დანარჩენი არ იცვლება.

სიდის ნომრები:

| ვინ | ნომერი |
|---|---|
| მძღოლი (ტრანსლაინი) | `+995599000301` |
| ხელოსანი (გიორგი ბ.) | `+995599000101` |
| ოპერატორი | `+995599000100` |
| უფროსი | `+995599000200` |

## როლები

| როლი | რას ხედავს | რა შეუძლია |
|---|---|---|
| `driver` | თავისი კომპანიის მანქანები და თიქეთები | გამოძახება, ნაწილის შეკვეთა |
| `tech` | მხოლოდ თავის თიქეთებს | ეტაპი, საათები, ჩანაწერი, ნაწილის შეკვეთა |
| `operator` / `admin` | ყველაფერს | მიბმა, ინვოისის გაგზავნა |

ეს არ არის მხოლოდ ინტერფეისის დამალვა — სერვერი თვითონ ჭრის: სხვისი თიქეთი → 403.

## Endpoints

```
GET    /health                          ბაზის მდგომარეობა (ტოკენის გარეშე)
POST   /auth/login                      { phone }
GET    /me
GET    /techs                           ხელოსნები + რამდენი თიქეთი აქვთ

GET    /trucks?q=                       ნომერი, VIN, მოდელი
GET    /parts?q=                        ჟარგონითაც: „შკორნი“ → ხუნდები
GET    /parts/:id

POST   /ai/triage                       { text } → ერთი დამაზუსტებელი კითხვა
POST   /ai/answer                       { symptomId, label } → ნაბიჯები + სავარაუდო ნაწილი

GET    /tickets?open=1&stage=&unassigned=1
POST   /tickets                         { truckId, issue, place, lat, lng }
GET    /tickets/:id
POST   /tickets/:id/assign              { techId }          ოპერატორი
POST   /tickets/:id/stage               { stage }
PATCH  /tickets/:id                     { note, hours }
POST   /tickets/:id/orders              { partId, supplierId, qty, delivery }
GET    /tickets/:id/invoice/preview     ანგარიში, არაფერი ინახება
POST   /tickets/:id/invoice             შექმნა და გაგზავნა     ოპერატორი
```

ეტაპები: `new → assigned → enroute → onsite → waiting_part → done → invoiced`.

## ორი წესი, რომელიც კოდშია ჩადებული

1. **ინვოისი ხელით არ იწერება.** `src/billing.js` კრებს თიქეთიდან: ნაწილი → მიტანა →
   გასვლა → საათები → დღგ. ამიტომ ვერაფერი დაგავიწყდება და ვერც ორჯერ ჩაიწერება.
2. **AI მხოლოდ ბაზიდან პასუხობს.** `/ai/*` სიმპტომების ცხრილში ეძებს. თუ ვერ იპოვა, ამბობს
   რომ ვერ იპოვა. ყოველ პასუხს თან ახლავს `confirmed` — დადასტურებულია თუ ვარაუდია.

## რა აკლია (შემდეგი ნაბიჯები)

- ფოტოების ატვირთვა (S3 ან ლოკალური საცავი) — ცხრილი ჯერ არ არის.
- SMS-კოდი შესვლისას.
- კურიერის გამოძახების ინტეგრაცია — ახლა მხოლოდ ფასი და სტატუსი იწერება.
- ინვოისის PDF და ე-ინვოისზე გატანა.
- მანუალების ინდექსი (pgvector) — Postgres-ზე გადასვლის შემდეგ.
- აპის მიერთება: `src/store.js` ჯერ კიდევ მეხსიერებაში მუშაობს.
